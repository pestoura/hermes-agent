# ADR-007 — Rules Engine purity & determinism

- **Status**: Accepted
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: HIGH

## Context

O Rules Engine é a fonte de verdade regulamentar (ADR-003). Para ser auditável e
reprodutível, e para que a separação de IA seja verificável por teste, o motor deve ser
determinístico e livre de efeitos colaterais.

## Decision

1. **Pure function contract**: `evaluate(input) → Decision` onde Decision é imutável e
   totalmente derivada do input + do rule package carregado.
2. **Proibição de efeitos colaterais**: o Rules Engine não faz I/O — não lê escreve do
   store nem do vault, não chama rede, não lê relógio, não gera UUID aleatório.
3. **Determinismo verificado**: golden test com seeds fixas — mesmo input + mesmo
   rule-package → output idêntico (byte-for-byte, excepto timestamp fora do motor).
4. **Linguagem-sugestão**: TypeScript puro (compilado e testado isoladamente).
5. **Entradas apenas schema-validadas**: o Domain Engine (Zona A) garante que input está
   validado antes; o motor re-valida defensiva (defense in depth).
6. **Open questions explícitos**: quando o motor não tem regra para um caso, devolve
   `Decision.unknown = { open_questions: [...] }` — nunca uma hipótese.

## Alternatives considered

- **A1 — Motor stateful (cache de decisões)**: mais rápido, mas violea reprodutibilidade e
  complica testes golden. Rejeitado.
- **A2 — Motor não-puro (lê store diretamente)**: acopla motor a storage impl, quebra
  isolamento e teste. Rejeitado.
- **A3 — Randomness seed (ex.: para sampling)**: proibido — quebra determinismo.
  Rejeitado.

## Consequences

- **Positivo**: teste golden automático; auditoria imediata; base sólida para AI separation.
- **Negativo**: performance de re-evaluação (aceitável para SME).
- **Reversível**: a linguagem é uma decisão de implementação; a contract `evaluate(input)`
  é a base. Ver ADR-007 v2 se performance exigir Rust.
