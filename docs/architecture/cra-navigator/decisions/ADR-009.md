# ADR-009 — Uploaded file safety validation

- **Status**: Accepted
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: HIGH

## Context

Evidências carregadas são a maior superfície de ataque (T-FILEUP, T-PATHTRAVERSAL,
T-ARCHIVE). O `frontend-sanitizer` (Zona C) limpa nomes e tipos, mas a validação de
integridade só é confiável com verificação de **magic bytes** no Evidence Vault (Zona B).

## Decision

1. **`Vault.validateSafety` corre antes de qualquer ingestão** e verifica:
   - **Magic bytes** da assinatura do ficheiro (não confia no content-type declarado).
   - **MIME spoofing**: mismatch entre content-type declarado e magic bytes → rejeição.
   - **Allowlist de tipos**: PDF, PNG/JPEG/GIF/WEBP, TXT/MD/CSV/Log, XLSX, ZIP/7z/RAR/TAR/GZ.
   - **Blocklist de extensões**: `.exe .dll .bat .sh .ps1 .js .vbs .jar .com .scr .msi`
     e `application/x-msdownload` / `application/x-executable`.
   - **Path traversal**: nome reduzido a leaf; rejeita `..`, `/`, `\`, NUL, `\\uXXXX`.
   - **Size cap** por tipo (PDF 50MB, imagem 25MB, texto 10MB, spreadsheet 30MB,
     archive 100MB).
2. **Archives**: extração sandboxing (temp folder), quote de membro (10.000), quota de
   membro individual (10MB), profundidade 5, tamanho total 200MB; re-aplica
   `validateSafety` a cada membro; member paths content-addressed.
3. **Content-addressing**: `EvidenceRecord.id = sha256(content)`; nome original só como
   metadado não-executável.
4. **Quarentena**: ficheiros ambíguos entram em `quarantine/` com estado
   `pending_review` (awaiting user approval), não no flow principal.

## Alternatives considered

- **A1 — Apenas content-type (rejeitado)**: trivially spoofable (T-FILEUP).
- **A2 — Antivirus integrado (rejeitado para MVP)**: depende de engine third-party +
  false positives; aumenta coupling. Reversível (D-02) como scanner opcional.
- **A3 — Não validar archives (rejeitado)**: T-ARCHIVE explícito.
- **A4 — Allowlist apenas por extensão (rejeitado)**: fraco contra rename de `.exe`→`.pdf`.

## Consequences

- **Positivo**: barra a maioria de ficheiros maliciosos na fronteira.
- **Negativo**: alguns ficheiros legítimos com headers não-categorizados entram em
  quarentena (UX de aprovação extra).
- **Reversível**: a allowlist/blocklist é config (`contracts/02-evidence-vault.yaml`).

## Revisão

- **Gate**: v1.0 — `mime_spoof_detected`, `path_traversal_rejected`, `zip_bomb_limit`,
  `content_addressing_idempotent` passam.
- **Owner**: backend-domain-engineer (w2).

## Threat model mapping

- T-FILEUP, T-PATHTRAVERSAL, T-ARCHIVE.
