# ADR-006 — Signed rule package & update integrity

- **Status**: Accepted
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: CRITICAL (MVP-blocking para confiança regulamentar)

## Context

O Rules Engine é a fonte de verdade regulamentar (ADR-003). Se um utilizador (ou atacante)
pudesse substituir o *rule package*, todas as decisões do produto seriam falsas — sem que
o utilizador percebia. Além diso, o mecanismo de atualização do app e do package deve
rejeitar releases corrompidos ou maliciosos (T-UPDATE).

## Decision

1. **Rule package é um bundle versionado e assinado**: `rules/v<semver>/` contém
   `cra-rules.yaml` + `manifest.json` + `manifest.json.sha256`. O `manifest.json` inclui
   `version`, `schema_version`, `source_refs[]`, `integrity_hash`, e uma assinatura
   Ed25519 do conteúdo.
2. **Verificação no boot**: o Rules Engine verifica `integrity_hash` (SHA-256 do bundle) e
   a assinatura com a **chave pública embutida** no app (trusted-root). Falha em qualquer
   verificação → engine não carrega; utilização limitada a leitura de dados existentes.
3. **Distribuição do package**: exclusivamente via Update Service (Fluxo 8), nunca pelo
   utilizador. Nenhum package do utilizador é aceite.
4. **Updates do app**: GitHub Releases; SHA-256 do asset comparado com o manifest;
   assinatura verificada com chave pública embutida; download apenas a `temp/`.
5. **Code signing**: todos os binários do app são assinados (SmartScreen). Cert autoridade
   definida no ADR-008 (reversível).
6. **Chave privada de assinatura**: não vive no repositório; workflow de release usa
   GitHub Environment + trusted signer (veja ADR-008).

## Alternatives considered

- **A1 — Package sem assinatura, apenas hash no repo (rejeitado)**: hash no repo público é
  facilmente forjado se o repo for comprometido; não protege contra substituição local.
- **A2 — Chave pública configurável pelo utilizador (rejeitado)**: abre a porta a
  key-substitution; a chave pública deve ser *trusted-root* embutida.
- **A3 — Auto-update sem assinatura (rejeitado)**: T-UPDATE CRITICAL.
- **A4 — Package do utilizador aceite (rejeitado)**: violea o princípio de fonte de verdade.

## Consequences

- **Positivo**: integridade regulamentar verificável; atualizações seguras.
- **Negativo**: release pipeline precisa de signer configurado (wave-3, ADR-008).
- **Reversível**: o formato do bundle pode evoluir (v2); a chave pública embutida é
  versionada via app update.

## Revisão

- **Gate**: v1.0 — `rule_package_tamper_detected` e `update_rejected_without_signature` passam.
- **Owner**: rules-reporting-engineer (w2) + desktop-packaging-engineer (w3) + DevOps (w1).

## Threat model mapping

- T-RULEPKG, T-UPDATE, T-DEPCOMP (supply chain de releases).
