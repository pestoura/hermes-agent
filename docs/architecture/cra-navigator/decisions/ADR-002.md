# ADR-002 — Versioned data model & migrations

- **Status**: Accepted
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: HIGH

## Context

O modelo de dados do CRA Navigator evoluirá (Issues #3, #4, e iterações de produto).
Sem versionamento e migrações, updates quebram o acesso ao store e invalidam backups.
A política do produto exige "modelo de dados versionado".

## Decision

1. **Schema semântico**: `schema_version` MAJOR.MINOR.PATCH no store header.
   - MAJOR: breaking (migração exigida).
   - MINOR: adição compatível (migração não-destrutiva).
   - PATCH: correção (sem breaking).
2. **Motor de migração**: script declarativo em `migrations/<from>-<to>.sql`, aplicado
   sequencialmente no boot do app, antes de qualquer leitura.
3. **Atomicidade**: cada migração usa `BEGIN IMMEDIATE` ... `COMMIT`; em falha, rollback
   automático. Registo em `migrations_log` (idempotente: re-run é no-op).
4. **Reversibilidade de schema-breaking**: colunas/tabelas a remover são movidas para
   `_pending_drop_<v>` e purgadas após 2 versões MAJOR (política ADR-002).
5. **Backup-aware**: o backup carrega `schema_version`; restore aplica migrações até a
   versão corrente do app.
6. **Contrato authoritativo**: `contracts/01-store-schema.yaml`.

## Alternatives considered

- **A1 — Schema-less (document/JSON) sem migração**: mais flexível mas perde type safety e
  rastreabilidade exigidas por `requirements-traceability-engineer`. Rejeitado.
- **A2 — Migração manual pelo utilizador (rejeitado)**: violea "auditability and
  reproducibility" e "operations are non-destructive".
- **A3 — ORM mágico sem controlo de versão (rejeitado)**: esconde breaking changes; falha
  `no_hidden_behavior_change` (definition-of-done).

## Consequences

- **Positivo**: updates seguros, backup/restore fiável, auditoria de schema.
- **Negativo**: overhead de manter migration scripts (mitigado por testes).
- **Reversível**: o motor de migração é uma interface (`contracts/06-migration.yaml`);
  pode trocar de ferramenta sem impacto no domínio.

## Revisão

- **Gate**: v1.0 — `store_migrate_preserves_data` e `backup_restore_roundtrip` passam.
- **Owner**: backend-domain-engineer (w2/w3).
