# ADR-005 — Cifragem em repouso & gestão de chaves (Windows DPAPI)

- **Status**: Accepted
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: HIGH (não bloqueia MVP mas é segurança desde o início)

## Context

O produto é local-first e guarda dados sensíveis do utilizador (evidências, decisões,
metadados). A política do repositório proíbe publicar segredos, mas os dados do utilizador
devem ser protegidos em repouso contra acesso físico ao disco ou a outro utilizador do SO
(T-DATASTORE, T-BACKUP).

## Decision

1. **Motor de base cifrada**: SQLCipher (AES-256-GCM, WAL mode) para o Local Store.
2. **Provedor de chaves**: `crypto-key-provider` usa o **Windows DPAPI**
   (`CryptProtectData`/`CryptUnprotectData`) para proteger o *master key wrapper*.
   - O master key (256-bit random) é gerado no primeiro boot e nunca persiste em texto.
   - DPAPI liga a chave ao utilizador Windows logado → isolamento por utilizador automático.
3. **Derivação de chave do SQLCipher**: `PBKDF2-HMAC-SHA256(master_key, salt, 200_000)`.
4. **Evidence Vault**: ficheiros binários em `%LOCALAPPDATA%\BlitzHub\CRANavigator\evidence/`,
   content-addressed (SHA-256). Cifra por-ficheiro opcional (quando `vault.encryption` = on),
   usando chave derivada do master key.
5. **Backup**: herdado do mesmo master key; exportação offline com password-derived key
   (PBKDF2, opcional, para backups portáteis).
6. **Localização**: `%LOCALAPPDATA%\BlitzHub\CRANavigator\` (ACL por utilizador Windows);
   nada fora desta pasta sem ação explícita do utilizador.

## Alternatives considered

- **A1 — Chave em ficheiro de config (rejeitado)**: expõe a chave a outro utilizador do SO
  ou a dumps de disco. Falha T-DATASTORE.
- **A2 — TPM-backed key (rejeitado para MVP)**: mais forte, mas requer provisionamento
  específico de hardware/TPM e complica o restore. Mantido como opção v2 (ADR-005 v2).
- **A3 — Cifra de metadata no app (client-side) com password do utilizador (rejeitado)**:
  UX pesada para SME; risco de password fraca. DPAPI oferece zero-friction para o MVP.
- **A4 — SQLCipher vs plaintext SQLite + app-level crypto (rejeitado)**: duplica a
  complexidade e risco de erros de implementação. SQLCipher é a camada canónica.

## Consequences

- **Positivo**: zero friction para o utilizador; isolamento por utilizador Windows; integridade.
- **Negativo**: restore do master key falha se o utilizador Windows for recriado sem DPAPI
  backup (mitigado pelo backup exportável com password).
- **Reversível**: o `crypto-key-provider` é uma interface (`contracts/04-crypto.yaml`),
  permitindo swap para TPM ou cloud KMS futuro sem tocar TZ-A.
