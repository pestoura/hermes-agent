# ADR-004 — Windows desktop delivery without Docker

- **Status**: Accepted
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: HIGH

## Context

A Issue #5 exige "modelo desktop Windows sem exigir Docker ao utilizador". A visão
(`docs/product/vision.md`) afirma "experiência utilizável por uma PME sem Docker ou
infraestrutura especializada". O bootstrapper confirma Issue #5 → solution_architect.

## Decision

1. **Empacotamento nativo Windows**: instalador `.msi` + `.exe` (NSIS), code-signed,
   sem runtime externo (tudo embutido — Node runtime + asar + SQLCipher).
2. **Zero dependência de Docker**: nenhuma parte do MVP exige Docker, container runtime ou
   WSL. Todo o processamento (Rules Engine, Evidence Vault, Report Generator) corre no
   mesmo processo do utilizador.
3. **Instalação per-user** (recomendado para SME): escreve apenas em
   `%LOCALAPPDATA%\BlitzHub\CRANavigator\` — ACL por utilizador Windows, **não requer
   elevate**.
4. **Atualização não-destructive**: patch incremental via Update Service (ADR-006);
   rollback automático após 2 boots falhos.
5. **Privilege boundary**: app roda como standard user; nenhuma escrita em `HKLM` ou
   `Program Files` no MVP.
6. **Compatibilidade**: Windows 10 21H2+ / Windows 11 (target mínimo definido pela
   política de qualidade).

## Alternatives considered

- **A1 — Imagem Docker obrigatória ao utilizador (rejeitado)**: violea o requisito
  explícito e a visão de produto.
- **A2 — WSL2 backend (rejeitado)**: exige componente opcional do Windows que a SME pode não
  ter; aumenta surface de ataque. Reversível como *opt-in advanced* (D-01), não MVP.
- **A3 — App portable-only (sem instalador, reversível)**: bom para utilizadores sem
  elevate, mas compli caixa UX de update. Mantido como segunda forma de distribuição
  (visão: "aplicação portátil"); instalador assinado é o caminho primário.
- **A4 — MSIX (rejeitado para MVP)**: requer store ou trust da firma; mais pesado para SME.
  Reversível como v2.

## Consequences

- **Positivo**: adotação imediata por SME; SmartScreen friend (assinatura); restore fácil.
- **Negativo**: empacotamento por-release (mitigado por electron-builder).
- **Reversível**: a stack de packaging não toca TZ-A/B/D core boundaries.

## Revisão

- **Gate**: v1.0 — build code-signed; smoke test de instalação per-user; teste de que o app
  não aparece em `taskmgr` com privilege elevado.
- **Owner**: desktop-packaging-engineer (w3).

## Threat model mapping

- T-WIN-PRIV, T-UPDATE.
