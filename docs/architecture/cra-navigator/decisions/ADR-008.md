# ADR-008 — Code signing & release integrity

- **Status**: Accepted (temporário, autoridade revertível — ver D-08)
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: HIGH

## Context

Empacotamento Windows (ADR-001, ADR-004) requer assinatura para SmartScreen. A política
CI impõe `privileged_workflows_require_trusted_ref: true` e proíbe `fork_secrets` /
`fork_write_token`. O bootstrapper exige "não publicar releases de produção" no MVP, mas
a arquitetura deve definir o caminho seguro até lá.

## Decision

1. **Assinatura de código**: Windows Authenticode (Embedded Signature) em todos os binários
   do app + asar + DLL native.
2. **Autoridade de certificado (temporária)**: EV Code Signing Certificate de autoridade
   pública conhecida (DigiCert/SecuroTrust/etc). [Reversível — D-08]
3. **Chave privada de assinatura**: **nunca** no repositório. Workflow de release usa
   GitHub Environment (`release`) com secret armazenado em GitHub Secrets, acesso
   limitado a membros da org + require approval.
4. **Assinatura do rule package**: Ed25519 (ADR-006), chave privada no mesmo GitHub
   Environment.
5. **CI gates** (`.github/workflows/validate-governance.yml` + release workflow):
   - `secret_scan` (universal).
   - `perfil do environment = trusted ref only` (proibido em forks).
   - `dependency_review` + `sbom`.
6. **Revogação**: pipeline automatizado para revogação em caso de compromisso (notificar
  `security@` + GitHub Security Advisory — `private_security_advisory_preferred: true`).

## Alternatives considered

- **A1 — Self-signed cert (rejeitado para produção)**: SmartScreen bloqueia; má UX para SME.
  Reversível para *dogfooding interno*.
- **A2 — Store Microsoft (MSIX) (rejeitado para MVP)**: exige conta de editor + tempo de
  aprovação; SME prefere instalador direto. Reversível como v2.
- **A3 — Chave no repo para CI (rejeitado)**: violea `public-repository-policy` e `T-SECRETS`.

## Consequences

- **Positivo**: SmartScreen passa; supply-chain de release protegida.
- **Negativo**: custo de cert (autoridade comercial) — decisão reversível até o primeiro
  release assinado (D-08).
- **Reversível**: authority do cert é adiada (D-08); o *trusted-root* do package (ADR-006)
  é versionado separadamente.

## Revisão

- **Gate**: v0.9 — build assinado passa em SmartScreen test; `secret_scan` não detecte
  chave no repo.
- **Owner**: desktop-packaging-engineer (w3) + devops-repository-engineer (w1) + release-engineer (w3).

## Threat model mapping

- T-SECRETS, T-DEPCOMP, T-UPDATE.
