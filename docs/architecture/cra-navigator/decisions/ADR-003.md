# ADR-003 — AI-assisted features are never authoritative

- **Status**: Accepted
- **Deciders**: blitzhub-cra-solution-architect
- **Date**: 2026-07-31
- **Issue**: #5 (ARCH-001)
- **Priority**: CRITICAL (MVP-blocking)

## Context

O produto (ver `docs/product/vision.md`) afirma: "A lógica regulamentar principal é
determinística e versionada. A Inteligência Artificial explica e melhora, mas não
substitui as regras controladas." A Issue #5 exige separação explícita de lógica
regulamentar determinística de funcionalidades assistidas por IA.

O CRA Navigator é uma ferramenta de *readiness* (não certificação). Contudo, se uma
conclusão regulamentar pudesse ser influenciada por output de IA, o produto perderia a
rastreabilidade exigida pelo `source-policy.yaml` (fact vs interpretation) e
pela qualidade do relatório (quality-gates).

## Decision

1. **O Rules Engine é a única fonte de verdade regulamentar.** Ele consome exclusivamente
   factos validados (Issue #3) e tabelas de decisão (Issue #4). Não tem acesso à IA nem a
   ficheiros do utilizador.
2. **A IA não escreve em decisões.** Todo output de IA é marcado `provenance=ai-assistant`,
   carrega `confidence (0.0–1.0)` e `traceId`. Output com confidence < 0.8 exige confirmação
   humana antes de qualquer efeito na UI.
3. **Fluxo obrigatório**: AI output → frontend-sanitizer → UI (confirmação) → Domain Engine
   (validado) → Rules Engine (re-decisão com base em factos) → Decision. A IA nunca é input
   direto do Rules Engine.
4. **AI é opt-in e offline.** Feature flag `ai.enabled` default a `false`. Quando a IA ou o
   runtime local LLM não estiverem disponíveis, a aplicação funciona 100% determinístico.
5. **Proveniência é obrigatória.** Todo output de IA e decisão do Rules Engine carrega
   proveniância no manifest de report (`provenance[]`).

## Alternatives considered

- **A1 — AI como co-piloto no Rules Engine (rejeitado)**: permite que a IA sugira
  obrigações/artigos. Rejeitado porque viopla o princípio de fonte de verdade e complica
  a rastreabilidade (fact vs interpretation). O risco de prompt injection é inaceptável para
  uma decisão regulamentar.
- **A2 — AI para fallback quando regra ausente (rejeitado)**: quando o Rules Engine não
  tem regra, a IA "preenche". Rejeitado: cria uma fonte de verdade fragmentada e permite
  que interpretacoes de IA se passem por factos. O Rules Engine devolve `unknown` com
  `open_questions` em vez disso.
- **A3 — AI sempre-on, confidence threshold mais baixo (0.5) (rejeitado)**: aumenta o risco
  de decisões influenciadas sem revisão. O threshold 0.8 foi mantido.
- **A4 — Cache de AI output como decisão (rejeitado)**: um chunk de AI em rascunho não
  submetido pode tornar-se "decisão" por erro de UI. Rejeitado: AI state é apenas UI state,
  nunca domínio.

## Consequences

- **Positivo**: rastreabilidade total; offline-first; auditável.
- **Negativo**: mais trabalho manual do utilizador para sumários/sugestões (aceição).
- **Teste exigido**: `ai_output_never_reaches_rule_decision`,
  `confidence_below_threshold_requires_human`, `deterministic_decision_stable`.

## Revisão

- **Gate**: v1.0 — AI opt-in implementado; validar golden test do Rules Engine com AI
  desativada vs ativada (output idéntico).
- **Owner**: rules-reporting-engineer (w2) + application-security-engineer (w3).
